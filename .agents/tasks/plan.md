# Implementation Plan — Foundation phase for `@solvejet/whatsapp-cloud-api`

This is **single-part scaffolding work**: tooling, CI/CD, and OSS docs for a TypeScript SDK of the
WhatsApp Cloud API. It does **NOT** decompose into separable features — it is one cohesive effort
that must end with a repo that installs, lints, formats-checks, typechecks, tests, and builds clean.
The existing implement-and-review loop implements this plan directly. No SDK features (messages,
templates, media, webhooks) are built here — only a minimal compiling `WhatsAppClient` skeleton.

## Environment facts (verified during exploration)

- Local toolchain: Node **v24.13.0**, pnpm **12.6.0** (corepack 0.34.7 available). npm 11.15.0.
- `engines.node` is `>=20`, so Node 24 local dev is valid. CI matrix still pins **20 and 22** per spec.
- **pnpm pin decision:** spec says pin "a recent stable pnpm (e.g. pnpm@9.x)". The lockfile MUST be
  generated by the same pnpm major that `packageManager` names, or CI `--frozen-lockfile` under that
  version can mismatch. Decision: pin `packageManager` to **`pnpm@9.15.9`** (latest stable 9.x) and
  generate `pnpm-lock.yaml` by invoking that exact version via corepack
  (`corepack pnpm@9.15.9 install`) so the committed lockfile matches the pinned pin and the CI
  `pnpm/action-setup@v4` (which reads `packageManager`). Rationale: keeps spec's pnpm@9.x intent while
  guaranteeing lockfile/CI consistency regardless of the newer pnpm 12 on PATH.
- **Dependency version decision:** install devDeps with caret ranges resolving to current stable
  (tsup ^8, vitest ^3 — see note, typescript ^5, eslint ^9, prettier ^3, typescript-eslint ^8). The
  registry currently also exposes very new majors (TypeScript 7, ESLint 10, vitest 5) that carry
  breaking changes and unstable flat-config/plugin interop. Decision: **pin to the proven stable
  majors** below rather than the absolute-latest tags, to keep flat ESLint config + typescript-eslint
  + vitest coverage interoperable without churn. If a chosen range fails to resolve/lint/test, the
  implementer may bump within the same major; do not jump to a new major without re-verifying lint+test.
